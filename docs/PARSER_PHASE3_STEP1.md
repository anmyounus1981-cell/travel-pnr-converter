# Phase 3 first wiring step: reviewed fallback

`lib/parser/adapter.ts` maps source-aware `ParseResult` into a **preview** of legacy `Conversion` fields. It preserves passenger and segment order, keeps type and cabin empty when unverified, and leaves flight timestamp fields blank. This preview must not be written to the current `timestamptz` database columns. Non-confirmed statuses and missing fields create blocking diagnostics; flight year and time-zone warnings retain original line spans.

`parsePnr()` in `lib/converter.ts` now executes the structured pipeline on every parse. It returns the existing dated conversion through a clearly labelled `legacy_fallback` state and attaches the independently parsed source and warnings as `parserReview`. It compares passenger counts and names, flight counts, routes and numbers between parsers and blocks discrepancies. Unsupported formats are reported as fallback rather than silently treated as recognized GDS. The old `parseLegacyPnr()` implementation remains responsible for flight years and dates until validated local-date storage and full adapter conversion are available. This is an intentional intermediate step, **not** a completed parser cutover.

`components/ParserDiagnostics.tsx` shows GDS, counts, original line ranges, status/RBD, unknown cabin and passenger type, review and blocking warnings. `app/Converter.tsx` runs it after Parse PNR and before Save, WhatsApp copy or History PDF download, then requires the agent to check the source review box. Raw-text changes clear that check. `app/api/conversions/route.ts` reparses raw text on POST, requires `reviewed_source: true`, rejects blocking discrepancies and invalid flight timestamps, and uses an explicit field allowlist to avoid writing client-supplied parser state into database columns. Both callers share `unresolvedBlockers()` to allow the dated legacy fallback only with an explicit agent review.

**Current limitations:** The review checkbox confirms a human action but does not prove the PNR details were correctly checked, and its acknowledgement is not persisted. Old saved records remain accessible through the authenticated direct PDF API even if an agent skips this new UI review flow. The existing timestamp columns can still interpret timezone-less local times as UTC. Date storage, provenance persistence, strict server-side export verification, tested real Amadeus formats and removing the old parser remain Phase 3 work. Avoid treating the fallback as verified flight-time data.
